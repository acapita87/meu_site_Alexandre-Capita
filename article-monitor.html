Azure Monitor, explained from scratch

Collect metrics and logs, build dashboards and fire alerts to keep your stack healthy.

What is Azure Monitor?

Azure Monitor is the observability service for Azure. It collects metrics (CPU, memory, disk) from all resources, stores application logs, and aggregates data from third-party tools. Use it to understand what's happening in your stack, troubleshoot problems, and catch issues before they escalate.

Metrics vs Logs

Metrics are numeric time-series data: CPU % over time, disk throughput, request count. Low cost, real-time. Logs are structured text: application output, error stacks, audit events. Higher storage cost, queryable after the fact. Use metrics for alerting (CPU > 80%?), logs for investigation (why did that job fail?).

Log Analytics Workspace

The Log Analytics Workspace is where logs live. Enable it, then resources send logs there. Query logs with KQL (Kusto Query Language): AzureDiagnostics | where ResourceType == 'VIRTUALNETWORKS' | summarize count() by TimeGenerated. Extremely powerful for digging into problems. First 5 GB/month free, then charged per GB.

Alerts & Action Groups

Create alert rules that fire when metrics cross thresholds. Example: "CPU > 80% for 5 minutes → send email + create incident". Alerts route to Action Groups which handle notification (email, SMS, webhook). Integrate with incident management systems (ServiceNow, Jira) so alerts trigger automated workflows.

Dashboards & Insights

Build custom dashboards pinning charts: VM performance, app latency, error rates. Insights are curated dashboards for specific resource types (VMs, App Service, SQL). They show health at a glance and link to detailed logs for troubleshooting. Most teams start with Insights, then customize.

Getting Started

Enable Monitor: resources automatically send metrics. Create Log Analytics Workspace for logs. Enable diagnostic settings on each resource (VMs, Load Balancers) to send logs to it. Create a simple alert: CPU > 80% → email. Build a dashboard with VM memory and disk charts. Query logs: Portal → Log Analytics → run KQL queries. Spend time in Insights to understand what's normal for your workload.
