Azure Firewall, explained from scratch

A managed, stateful network firewall with threat intelligence to protect your VNets.

What is Azure Firewall?

Azure Firewall is a managed, cloud-native firewall that sits between your VNet and the internet. Unlike NSGs (which are lightweight), Azure Firewall is a full-featured appliance: it inspects all traffic at layer 7, blocks malware, applies threat intelligence, and logs everything for audit.

Network vs Application Rules

Network rules work at layers 3-4 (IP, TCP, UDP): allow/deny by source IP, destination IP, port, protocol. Application rules work at layer 7 (HTTP/HTTPS, DNS): inspect hostnames, URLs, and headers. Example: deny all outbound traffic except to microsoft.com and github.com. This is far more granular than a simple NSG.

Threat Intelligence & Logging

Azure Firewall has threat intelligence built-in: it knows about known malicious IPs, domains, and attack patterns. Enable it to auto-block known-bad traffic. All traffic decisions are logged to Azure Log Analytics: which connections succeeded, which were denied, why. Use these logs to tune rules and audit compliance.

Firewall Policies & Central Management

Create firewall policies and apply them to multiple firewalls across your organization. This centralized approach keeps rules consistent: one policy defines allowed traffic for all environments. Policies can be inherited and overridden at the VNet level — powerful for large deployments with multiple teams.

Getting Started

Deploy Azure Firewall: Portal → Firewalls → Create. Place it in a hub VNet with subnets connected via peering. Configure inbound & outbound rules. Enable threat intelligence. Route traffic through the firewall: create route tables pointing to the firewall's IP. Monitor logs in Log Analytics. Start permissive (log everything), then tighten rules as you understand your traffic patterns.
