Network Security Groups, explained from scratch

Filter inbound and outbound traffic to your subnets and NICs with simple, prioritized rules.

What is a Network Security Group?

A Network Security Group (NSG) is a stateful firewall for your VNet. It contains inbound rules (what traffic can enter) and outbound rules (what traffic can leave). You attach an NSG to a subnet (affecting all VMs) or a single NIC. Azure evaluates rules by priority — first match wins.

Inbound Rules

Define what traffic can reach your VMs. Example rules:

  • Allow TCP 22 (SSH) from 10.0.0.0/8 (corporate network)
  • Allow TCP 80 & 443 (HTTP/HTTPS) from 0.0.0.0/0 (internet)
  • Allow TCP 3389 (RDP) from 203.0.113.0/24 (your office IP)
Default: deny all. Only add rules for what you actually need.

Outbound Rules

Control what leaves your VMs. By default, all outbound is allowed. You can restrict: block downloads from untrusted sites, limit cloud API calls, or force all traffic through a proxy. Most beginners leave defaults and only tighten when security reviews demand it.

Priority & Stateful Matching

NSGs are stateful: if you allow SSH inbound, the response traffic is automatically allowed outbound. Rules have priority numbers (100–4096). Lower numbers evaluate first. A deny at priority 100 blocks everything before an allow at priority 200. Use ranges: 100s for critical rules, 1000s for exceptions.

Getting Started

Create an NSG: Portal → Network Security Groups → Create. Add inbound rules for services you need (SSH, HTTP). Attach it to a subnet or NIC. For troubleshooting, use Azure Network Watcher to trace why traffic is blocked. Common mistake: forgetting to open a port, then wondering why your app is unreachable.
