VM Scale Sets, explained from scratch

Run and auto-scale identical VMs behind a load balancer to handle traffic spikes automatically.

What is a VM Scale Set?

A VM Scale Set (VMSS) is a group of identical, auto-scaling VMs that can grow or shrink automatically based on demand. Instead of managing each VM individually, you define a template once, and Azure handles creating, updating, and removing VMs as traffic changes.

How Autoscaling Works

Scale Sets use autoscaling rules connected to Azure Monitor metrics. You set a target: if CPU goes above 70%, scale up; if it drops below 20%, scale down. Azure continuously watches and adjusts the instance count in seconds, keeping your app responsive without manual intervention.

Key Concepts

  • Instance template — defines the VM configuration (OS, size, disks, network).
  • Scaling rules — trigger scale-up/down based on metrics or schedules.
  • Health probes — remove unhealthy VMs and replace them automatically.
  • Load balancer integration — traffic flows through Azure Load Balancer to spread load.

Getting Started

Create a Scale Set from the Portal: choose an image, define min/max instance count, select an autoscale rule. For CLI: az vmss create --resource-group myRG --name myScaleSet --image UbuntuLTS --capacity 2. After creation, add autoscaling: az monitor autoscale create --resource-group myRG --resource myScaleSet --resource-type "Microsoft.Compute/virtualMachineScaleSets".

Best Practices

  1. Use health probes — so Azure removes broken instances fast.
  2. Test autoscale rules — load-test to verify they trigger correctly.
  3. Monitor costs — autoscaling can spin up many VMs; set hard max limits.
  4. Keep templates clean — use images, not custom scripts, for faster scale-up.
