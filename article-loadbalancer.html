Azure Load Balancer, explained from scratch

Distribute traffic across healthy VMs at layer 4 for high availability and scale.

What is a Load Balancer?

The Azure Load Balancer is a layer-4 (transport layer) device that sits in front of your VMs and distributes incoming traffic across them. When requests arrive, it spreads them based on rules: round-robin, least connections, or IP hash. This prevents any single VM from getting overloaded.

Frontend & Backend Pools

Every Load Balancer has:

  • Frontend IP — the public or private address clients connect to.
  • Backend pool — the group of VMs receiving traffic (usually 2–10 VMs).
  • Health probes — checks if each VM is healthy; removes dead ones automatically.
Traffic flows: Client → Frontend IP → Load Balancer → Health check → Backend pool.

Load Balancing Rules

A load balancing rule maps incoming traffic to backend VMs. Example:
Frontend IP 203.0.113.1:80 → Backend pool VMs:8080
This listens on port 80 (HTTP) and sends to backend VMs on port 8080. You can have multiple rules: one for HTTP, one for HTTPS, one for SSH. Each rule defines protocol (TCP/UDP), ports, and algorithm.

Health Probes & Failover

The Load Balancer continuously pings backend VMs (HTTP GET, TCP port check) to ensure they're healthy. If a VM stops responding, it's automatically removed from the pool — traffic stops flowing to it. When it recovers, it's added back. This is automatic high availability: clients never see a dead VM.

Getting Started

Create a Load Balancer: Portal → Load Balancers → Create. Choose public or private. Add a frontend IP and backend pool (select your VMs). Create a health probe (HTTP on port 80, path /health). Create a load balancing rule (port 80 → backend port 80). Deploy at least 2 VMs for redundancy. The LB's public IP becomes your app's endpoint.
