Azure Key Vault, explained from scratch

Safely store secrets, keys and certificates, and keep them out of your code and configs.

What is Key Vault?

Azure Key Vault is a secure vault for passwords, API keys, database connection strings, and SSL certificates. Instead of hardcoding secrets in your app or config files, store them in Key Vault and reference them at runtime. Azure handles encryption, access control, and audit logging.

Secrets, Keys & Certificates

  • Secrets — arbitrary strings (passwords, connection strings, API keys).
  • Keys — cryptographic keys for encryption (RSA, EC). Your app encrypts with Key Vault's key without ever seeing it.
  • Certificates — SSL/TLS certificates for HTTPS. Key Vault can auto-renew them before expiry.
All three are encrypted at rest and in transit. Only authorized apps can read them.

Access Control & Managed Identity

Grant access using role-based access control (RBAC) — assign "Key Vault Secrets Officer" to a team. For apps, use Managed Identity: give your VM or App Service an identity, then assign it permissions to read specific secrets. Your app uses that identity automatically; no credentials needed in code.

Versioning & Soft Delete

When you update a secret, Key Vault keeps the old version. Your app can reference a specific version or always get the latest. Soft delete means deleted secrets aren't gone immediately — they're recoverable for 90 days. This prevents accidental data loss from automation or mistakes.

Getting Started

Create a Key Vault: Portal → Key Vaults → Create. Choose access model (RBAC or policy). Add secrets manually or via CLI: az keyvault secret set --vault-name myVault --name DBPassword --value mypassword. From your app (Node.js, .NET, Python), use the SDK to fetch secrets. Enable logging to track who accessed what. For VMs, use Managed Identity for frictionless access.
