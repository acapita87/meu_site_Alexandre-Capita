Application Gateway, explained from scratch

Layer-7 load balancing with SSL offload, URL routing and a built-in Web Application Firewall.

What is Application Gateway?

Application Gateway is a layer-7 load balancer that understands HTTP/HTTPS. Unlike a simple layer-4 Load Balancer, it can inspect the content of requests and route based on URL paths, hostnames, or headers. It also terminates SSL/TLS, offloading encryption work from your backend VMs.

URL Routing & Hostnames

Route requests based on the URL path:

  • /api/* → API backend VMs
  • /images/* → image server
  • example.com → one pool, cdn.example.com → another
This lets you use a single public IP for multiple applications or services, each with its own backend pool. The Gateway inspects headers and decides routing in milliseconds.

SSL/TLS Offload & WAF

Upload your SSL certificate to Application Gateway. It terminates HTTPS connections from clients, then talks to backend VMs over plain HTTP (or re-encrypted HTTPS). This offloads CPU-intensive encryption from your VMs.
Web Application Firewall (WAF) is built-in: it blocks common web attacks (SQL injection, XSS, DDoS). You choose detection or prevention mode.

Backend Health & Sticky Sessions

Application Gateway monitors backend health with HTTP probes (GET /health). Failed VMs are removed; healthy ones handle traffic. Session affinity (sticky sessions) keeps a client's requests going to the same backend VM — useful for apps that store session state locally. Without it, each request might hit a different VM.

Getting Started

Create Application Gateway: Portal → Application Gateways → Create. Define frontend IP & port (443 for HTTPS). Upload SSL certificate. Create backend pools (groups of VMs). Define routing rules (path or host based). Add WAF if security is critical. Point your domain DNS to the gateway's public IP. Test routing by accessing different paths.
