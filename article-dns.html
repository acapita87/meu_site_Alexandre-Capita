Azure DNS, explained from scratch

Host your domains in Azure and resolve names for public and private workloads.

What is Azure DNS?

Azure DNS lets you host your domain and manage DNS records in Azure instead of a third-party registrar. Point your domain's nameservers to Azure, and Azure resolves queries (example.com → 203.0.113.1). You can manage A records, CNAME, MX, TXT, and more all in the Portal or CLI.

Public vs Private DNS Zones

Public DNS zones resolve names for internet-facing apps: your web server, API, CDN. Private DNS zones resolve names only within a VNet: databases, internal APIs, services. Both use the same interface, but private zones are linked to specific VNets and not queryable from the internet.

Common Records

  • A record — maps a domain to an IPv4 address (example.com → 203.0.113.1).
  • CNAME — alias one domain to another (www.example.com → example.com).
  • MX record — specifies mail server (mail.example.com).
  • TXT record — arbitrary text, used for SPF, DKIM, domain verification.
  • AAAA record — IPv6 address mapping.

Alias Records

Azure DNS supports alias records — special records that point to Azure resources (Load Balancers, Application Gateways, Storage accounts). Unlike CNAME records, alias records work at the zone apex (example.com, not just www.example.com). This is powerful: your domain automatically follows your Load Balancer's IP if it changes.

Getting Started

Create a DNS zone: Portal → DNS zones → Create. Enter your domain (example.com). Azure gives you 4 nameservers. Update your domain registrar to point to those nameservers. Add records (A, CNAME, MX) in the Portal. Changes propagate in minutes to hours globally. Use Azure DNS + Load Balancer alias record for high availability: if the LB moves, DNS automatically follows.
