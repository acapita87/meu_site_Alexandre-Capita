ARM & Bicep Templates, explained from scratch

Define your infrastructure as code so deployments are repeatable, reviewable and reliable.

Infrastructure as Code

Infrastructure as Code (IaC) means defining your cloud resources in code files instead of clicking through the Portal. Use ARM templates (Azure Resource Manager JSON) or Bicep (a simpler language). Benefits: repeatable deployments, version control, peer review, disaster recovery.

ARM Templates

ARM is JSON. A template defines all resources: VMs, networks, storage. Example:
{ "type": "Microsoft.Compute/virtualMachines", "apiVersion": "2021-03-01", "name": "myVM", ... }
Powerful but verbose. You'll write a lot of JSON. Good for large enterprises with strict governance. Use parameters for values (region, VM size) so one template deploys everywhere.

Bicep

Bicep is a newer, simpler syntax that compiles to ARM JSON. Example: param location string = 'eastus'
resource vm 'Microsoft.Compute/virtualMachines@2021-03-01' = { ... }
Much more readable. Recommended for new projects. Growing ecosystem of community modules. Compiles behind the scenes to ARM, then deploys the same way.

Parameterization & Modules

Extract common patterns into modules. Example: a VNet + NSG + subnet module. Reuse it across projects, just pass parameters (address space, rules). Version modules in a registry. This prevents copy-paste and keeps standards enforced.

Getting Started

Learn Bicep (easier than ARM). Write a simple file: VNet + VM + NSG. Test locally with az bicep build --file main.bicep. Deploy: az deployment group create --resource-group myRG --template-file main.json. Store templates in Git. Add CI/CD: validate templates before PR merge. Start small, grow your template library. Eventually, you deploy infrastructure by updating a Git repository.
