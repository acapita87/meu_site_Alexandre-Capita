Azure Virtual Machines, explained from scratch

A Virtual Machine is the most direct way to run your own server in the cloud. Here's what that really means, what it costs, and how to launch your first one in minutes.

What is a Virtual Machine?

An Azure Virtual Machine (VM) is a computer that lives in Microsoft's datacenters instead of on your desk. You choose how much CPU, memory and disk it has, pick an operating system, and Azure gives you a fully working server you can log into within minutes — and shut down just as quickly.

This model is called Infrastructure as a Service (IaaS): Microsoft manages the physical hardware, power, cooling and networking, while you manage the operating system and everything you install on top. It's the cloud building block that feels most like a traditional server, which makes it the perfect place to start.

Analogy: Renting a VM is like renting an apartment instead of buying a house. You get a space that's yours to use, you pay only while you live there, and the landlord (Azure) handles the building itself.

The anatomy of a VM

Every VM you create is actually a small bundle of resources working together. Understanding these pieces makes everything else in Azure click into place:

  • Compute — the virtual CPU and RAM, defined by the VM size.
  • OS & data disks — managed disks that store your operating system and files.
  • Network interface (NIC) — connects the VM to a Virtual Network.
  • Public IP (optional) — makes the VM reachable from the internet.
  • Network Security Group — the firewall rules controlling who can connect.

Sizes & pricing

VM sizes are grouped into families optimized for different jobs. You don't need to memorize them — just know the general shape:

FamilyBest forExample
B-seriesBurstable, low-cost dev/testB2s
D-seriesGeneral-purpose productionD4s_v5
F-seriesCompute-heavy workloadsF8s_v2
E-seriesMemory-hungry appsE16s_v5

You're billed per second while a VM is running. The single biggest way to save money as a beginner: stop and deallocate VMs you aren't using — you stop paying for compute the moment you do.

Watch out: stopping a VM from inside the OS still bills you. Always “Stop (deallocate)” from the Azure Portal or CLI to actually release the hardware.

Deploy your first VM

You can create a VM in the Portal with a few clicks, but the cleanest way to learn is the Azure CLI — one command captures every decision you just read about:

azure-cli · bash 
# 1. Create a resource group to hold everything
az group create --name rg-learn-azure --location westeurope

# 2. Create a Linux VM inside it
az vm create \
  --resource-group rg-learn-azure \
  --name my-first-vm \
  --image Ubuntu2204 \
  --size Standard_B2s \
  --admin-username azureuser \
  --generate-ssh-keys

That's it. In about a minute Azure returns the VM's public IP address, and you can connect:

bash 
ssh azureuser@<public-ip>

Beginner tips that save real money

  1. Use B-series for learning. They're cheap, burstable, and perfect for experiments.
  2. Deallocate when idle. Set an auto-shutdown schedule in the VM's settings.
  3. Tag everything. Tags make it easy to find and clean up resources later.
  4. Delete the whole resource group when a lab is done — it removes the VM, disk, NIC and IP in one action.

Next step: a VM alone isn't very useful until it's connected and protected. Continue with Virtual Networks and Network Security Groups to make yours reachable and safe.
